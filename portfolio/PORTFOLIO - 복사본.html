1. 시스템 아키텍처

이커머스 운영의 실제 문제 8가지를 AI로 해결하는 풀스택 데모 프로젝트. 빠른 규칙을 먼저 적용하고, 규칙으로 판단이 안 되면 AI가 넘겨받는 하이브리드 구조입니다.

해결하는 문제

문제 기존 방식 AI 플랫폼 솔루션
셀러 이탈 이탈 후 사후 분석 RandomForest + SHAP 사전 예측 + 원인 분석
이상거래 수동 모니터링, 신고 기반 Isolation Forest 실시간 자동 탐지
CS 문의 담당자 수동 분류/응답 TF-IDF + RF 자동 분류 + RAG+LLM 답변 + DnD 자동/수동 분기
정산 이상 수작업 검증 DBSCAN 이상 패턴 탐지
매출 예측 경험 기반 추정 LightGBM 다변량 매출 예측
데이터 분석 SQL 직접 작성 자연어 질의 → AI 에이전트 자동 분석 (31개 도구)
DB 보안 수동 모니터링 룰엔진 + ML + LangChain Agent 3단계 실시간 차단

핵심 설계 원칙

프로젝트 전반에 일관되게 적용한 "빠른 규칙 우선 + AI fallback" 원칙:

적용 영역 1차: 규칙 기반 (빠름, 비용 0) 2차: AI fallback (정확, 비용 발생)
에이전트 라우터 키워드 사전라우팅 → 워커 직접 호출 (0ms) Supervisor LLM 판단 (gpt-4o-mini)
DB 보안 감시 룰엔진 (<1ms) LangChain Agent (3~8초)
CS 파이프라인 신뢰도 >= 0.75 자동 처리 신뢰도 < 0.75 담당자 검토
ML 예측 Heuristic 스코어링 ML 모델 (RandomForest, LightGBM)

설계 기반: Anthropic Building Effective Agents — "빠른 규칙 우선 + AI fallback" 패턴을 이커머스 운영에 적용

2. AI 에이전트

3개 전문 워커(search/analysis/cs)가 도구를 분담하는 Supervisor 멀티에이전트 시스템. 명확한 질문은 키워드 매칭으로 즉시 처리하고, 모호한 질문만 LLM이 판단합니다.

하이브리드 라우팅 (키워드 + Supervisor)

명확한 intent는 키워드 매칭으로 워커를 즉시 호출(~1~3초 절감)하고, 모호한 질문만 Supervisor LLM이 판단합니다.

3. RAG 시스템 (4종 활성 + 4종 확장)

FAISS + BM25 Hybrid 검색을 중심으로 4종 기법을 활성 적용하고, 4종을 추가 확장 가능하도록 모듈화했습니다. 단일 검색으로는 놓칠 문맥까지 잡아냅니다.

적용 기법 요약

# 기법 효과 논문/출처 상태
1 Hybrid Search (FAISS + BM25 + RRF) 의미 + 키워드 검색 결합 - 활성
2 RAG-Fusion (Multi-Query) 2개 쿼리(원본 + 1개 변형)로 리콜 향상 - 활성
3 Parent-Child Chunking 정밀 검색(500자) + 충분한 컨텍스트(3,000자) - 활성
4 Contextual Retrieval 검색 정확도 +20~35% (Anthropic 벤치마크) Anthropic 활성
5 LightRAG (GraphRAG) 경량 지식 그래프, 99% 토큰 절감 (논문 기준, vs GraphRAG) arXiv:2410.05779 시험용
6 K2RAG KG + Hybrid (Dense 80%+Sparse 20%) + Corpus 요약 93% 시간 절감 arXiv:2507.07695 시험중
7 CRAG (Corrective RAG) 검색 품질 자동 교정 arXiv:2401.15884 모듈 완료
8 Cross-Encoder Reranking 정밀 재순위 - 비활성

Hybrid Search (FAISS + BM25 + RRF)

쿼리 → FAISS(의미적 유사도) + BM25(키워드 매칭) → RRF 병합 → 최종 결과

Parent-Child Chunking

레벨 크기 용도
Child 500자 검색 인덱싱 (정밀 매칭)
Parent 3,000자 최종 반환 (충분한 문맥)

LightRAG (지식 그래프)

쿼리 → Local(엔티티 중심) + Global(테마 중심) → Hybrid 병합 → 결과

Corrective RAG (CRAG)

검색 결과를 LLM이 자동 평가하여, 품질이 낮으면 쿼리를 재작성하고 재검색합니다.

flowchart LR Q["쿼리"] --> S["검색"] --> G{"Retrieval Grader"} G -->|"CORRECT"| USE["바로 사용"] G -->|"INCORRECT"| RW["Query Rewriter"] --> S2["재검색 · 최대 2회"] G -->|"AMBIGUOUS"| RW

4. ML 파이프라인 (12개 모델)

6종 알고리즘으로 12개 ML 모델을 구축. 사용자가 자연어로 질문하면 에이전트가 적절한 모델을 골라 실행하고, MLflow가 모든 실험을 추적합니다.

설계 원칙

  • AI 에이전트 통합: 에이전트가 Tool Calling으로 ML 모델을 호출합니다. 사용자가 자연어로 질문하면 에이전트가 적절한 모델을 골라 결과를 자연어로 설명합니다.
  • MLflow 추적: MLflow가 모든 학습 실험을 기록하고, 프론트엔드에서 모델 버전을 선택하면 실시간으로 교체합니다.
  • Graceful Degradation: LightGBM/XGBoost가 없으면 scikit-learn 기본 알고리즘으로 자동 대체합니다.

이탈 방지 자동 조치

단계 기능 기술
1. 탐지 이탈 확률 ≥ 임계값(기본 60%) 셀러 배치 탐지 RF predict_proba + SHAP Top-5 요인 추출 (ML 없으면 휴리스틱 폴백)
2. 메시지 SHAP 이탈 요인 + 셀러 프로필 기반 맞춤 메시지 GPT-4o-mini (JSON 응답: message + recommended_actions + urgency)
3. 조치 coupon(수수료 30% 할인 30일) · upgrade_offer(Premium 3개월 무료) · manager_assign(24h 내 연락) · custom_message(LLM 생성) 4종 action_type · 벌크 실행 지원 (/retention/execute-bulk)
4. 추적 pipeline_id로 단계별 상태 추적 (pending → processing → complete) Action Logger (thread-safe, 최대 5,000건)

위험 등급: 이탈 확률 > 70% → high, 30~70% → medium, < 30% → low. 모델 미설치 시 접속 경과일·주문수·매출·환불률·CS 문의 건수 5개 지표로 휴리스틱 점수를 산출합니다.

플랜 업그레이드 자동 추천

셀러의 매출과 주문수가 현재 플랜 임계값을 초과하면 상위 플랜을 추천합니다. 업그레이드 점수는 매출 비율 60% + 주문 비율 40%로 0~100점 산출합니다.

현재 플랜 추천 플랜 매출 기준 주문수 기준
Basic Standard ≥ 500만원 ≥ 100건
Standard Premium ≥ 2,000만원 ≥ 500건
Premium Enterprise ≥ 5,000만원 ≥ 2,000건
단계 기능 기술
1. 탐지 매출/주문수 임계값 기반 업그레이드 후보 탐지 매출 ≥ 임계값 or 주문수 ≥ 임계값 → 후보 필터링
2. 분석 셀러 성과 데이터 종합 분석 매출 60% + 주문수 40% 가중 점수 (0~100) + 성장 지표(상품수, 환불률, 접속빈도)
3. 메시지 상위 플랜 혜택 기반 맞춤 업그레이드 추천 메시지 GPT-4o-mini (JSON: message + benefits + urgency)
4. 실행 업그레이드 추천 / 혜택 안내 / 상담 예약 / 맞춤 메시지 발송 upgrade_recommend · benefit_info · consultation_request(48h 내) · custom_message

CS FAQ 자동 생성

단계 기능 기술
1. 분석 카테고리별 CS 문의 TF-IDF 벡터화 + 실루엣 최적 K 탐색 TF-IDF(max_features=500) + 실루엣 최적 K 탐색(k=2~min(n÷8, 10)) / LLM: GPT-4o-mini(최대 50건, temp 0.3)
2. 클러스터링 K-Means or LLM 의미 그룹핑 (듀얼 모드) K-Means(n_init=10, random_state=42) + PCA 2D 좌표 → 산점도 시각화 / LLM 의미 그룹핑
3. 선택 클러스터별 체크박스로 원하는 클러스터만 선택 프론트엔드 체크박스 → selectedClusters 배열 전달 → 재분석 생략
4. 생성 선택된 클러스터 x 클러스터당(1~3) FAQ 자동 생성 GPT-4o-mini(temp 0.7) → JSON [{question, answer, category, tags}] · 9개 카테고리
5. 검토/승인 관리자가 FAQ 확인 · 편집 후 승인/삭제 draft 상태 저장 → 편집/삭제 → approved 전환 · FAQ CRUD API 4개
